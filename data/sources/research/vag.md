# VAG group (Skoda, Seat, Cupra, Volkswagen, Audi) - report

## Summary
- 99 schedule files, 480,239 registry vehicles matched (96.5% of the 497,843 VAG vehicles in registry-counts.json). 48 reviewed, 51 draft. `registry_rules.json` has one rule per file/make with engine_codes (3-letter degem_manoa) and fuel.
- `node scripts/validate.mjs` passes on the schedule files (`all schedules valid (51 draft, 48 reviewed)`); when run on the whole staging dir it also tries to parse `registry_rules.json` as a schedule and reports it (15 'missing key' errors) - not a schedule file.
- Files were generated by a script from shared templates (VAG uses the same service tables across brands per platform/engine family); one file per make+model(+generation)+engine family so the app shows the right make/model. Mapping is by engine code.

- Audi maintenance manuals (Q3 2012, A4 2015) have no interval tables (Audi keeps them in ElsaPro) -> Audi pre-2019 petrol files use VW tables for the same engine (draft).
- Not found: Skoda service plan booklets, Seat 'Maintenance programme' booklets, VW 'Service schedule' booklets (not published online). No maintenance manual found for Octavia II, Fabia II, Roomster, Yeti, Superb II, Ibiza 6J, Leon II, Polo 6R, Jetta 6, Golf 6 -> used the closest same-brand manual with the same engines (said in each file's notes). vwts downloads of Beetle 2012 and Octavia IV 2025 manuals failed (upstream errors).
- Registry make 'קופרה' is not in lookup_plate MAKES, so normalizeMake returns 'קופרה'; the 2 Cupra files use make 'קופרה' in registry_rules (suggest adding ["קופרה","Cupra"] to MAKES and changing the rule make).
